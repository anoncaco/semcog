# ADR-0001: Direct Developer Registry Path (개발자 직접 등록 경로)

- **상태:** 확정 (Accepted)
- **일자:** 2026-10-20
- **관련:** `summary_arch.md` §2 C11, §7.5.1 (신설), §7.7, §8.6, §16 Phase 12, §19 #12
- **기반:** 아키텍처 검토 M1 (구조적 공백 — 문서 내부의 논리적 결함)

## 배경

`summary_arch.md` v1.2에는 다음 규칙이 동시에 존재했다.

- §7.3: 관계 규칙 추가 = §7.9의 `add_relation_type` **구조 변경**
- §7.9: 구조 변경 수명주기 = **META가 제안** → 격리 샌드박스 → 회귀 → 승인 → 버전 생성 → 롤백
- §7.7: "Phase 6 이후에 연산을 추가하려면 Phase 12(META)가 먼저 완료돼야 한다"
- §16: `configs/relations.yaml`은 **Phase 3** 산출물, 5개 기본 연산은 **Phase 6** 산출물, META는 **Phase 12** 산출물

META 제안 경로가 존재하지 않는 Phase 3~11에서, 구조 변경이 필요한 산출물을 만들 방법이 문서에 없었다. §7.7이 명시적으로 예외를 둔 것은 "Phase 6 **이후**"뿐이어서, Phase 3의 `relations.yaml` 작성과 Phase 6의 최초 연산 등록은 여전히 규범상 불가했다.

**결과:** 규범대로라면 Phase 3 착수 시점에 이미 막힌다. 문서 3개가 서로 충돌하는 상태.

## 검토한 대안

| 대안 | 평가 |
|---|---|
| (a) META-v1을 Phase 3으로 앞당김 | Phase 12가 META를 다루는 이유를 무시한다. 샌드박스·롤백·구조 버전이 아직 무의미한 시점에 META를 만들어 낭비한다. **기각** |
| (b) §7.9 수명주기에서 META 의존성을 제거 | META를 무의미하게 만든다. §7.9·Phase 12가 사라진다. **기각** |
| (c) §7.7 예외를 "Phase 6 이후 → Phase 12 이후"로 확대 | §7.3(Phase 3 규칙)의 경로가 여전히 없다. **불충분** |
| **(d) 개발자 직접 등록 경로를 Phase 3~11에 한해 허용** | **채택.** META는 Phase 12에서 유일한 제안자가 된다 |

## 결정

**Phase 3~11 개발 기간에는 개발자가 선언적 구조를 직접 변경할 수 있다.** 단, 게이트 4조건을 모두 통과해야 한다.

1. **버전 bump** — 변경 대상에 버전 식별자를 부여하고 올린다. 동일 버전의 다른 값과 섞지 않는다.
2. **회귀 green** — `tests/regression/` 전체와 해당 모듈의 단위 테스트가 통과한다. 실패 시 변경은 완료된 것으로 취급하지 않는다.
3. **ADR 기록** — `docs/decisions/`에 사유·영향·측정 결과를 기록한다.
4. **버전 전파** — 변경된 구조 버전이 `STATE.structure_version`과 모든 `InferenceTrace.rule_version`에 기록된다.

적용 대상은 **선언적 구조만**이다: `configs/relations.yaml`, `configs/attributes.yaml`, `configs/goal_rules.yaml`, `configs/structure_registry.yaml`, `reasoning/registry.py`.

변경 레코드는 §8.6 `StructureChangeProposal`으로 남기되 `proposed_by=developer`로 표기한다(META 제안과 구분 가능해야 함).

**Phase 12 이후**에는 개발자 경로를 폐기하고 META 경로로 일괄 이관한다. **이관 자체가 Phase 12의 산출물**이며, 변환 전 레코드를 보존하고 되돌릴 수 있어야 한다.

## 결과

- Phase 3~11이 규범적으로 진행 가능하다.
- META의 권한은 훼손되지 않는다. META는 Phase 12 이후 유일한 구조 변경 제안자가 된다.
- 구조 변경 이력이 Phase 12부터 META 이력으로 재현 가능하게 변환된다.
- **원칙은 유지된다:** 임의 소스 코드 수정 금지(P9 계열), 구조 변경과 파라미터 학습 분리(P12), 승인·버전 기록·롤백 가능(P6).

## 대안안의 잔여 위험

- 개발자 경로가 사실상 "승인 없는 변경"으로 변질될 위험 → 게이트 2(회귀 green)가 이를 막는다. 회귀가 없는 변경은 승인되지 않는다.
- 이관 과정에서 이력이 손상될 위험 → Phase 12 게이트에 "변환 전 레코드 보존 + 되돌리기 가능"을 명시했다.
