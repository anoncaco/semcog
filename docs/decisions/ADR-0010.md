# ADR-0010: B0–B7 단일 변인 통제와 leave-one-out 대조

- **상태:** 확정 (Accepted)
- **일자:** 2026-10-20
- **관련:** `summary_arch.md` §12.2, §15.1, §15.2, §15.3, §15.4, §16 Phase 10
- **기반:** 아키텍처 검토 Phase 10 §3

## 배경

§15.1은 B0–B7을 **누적 스택**으로 정의한다.

| ID | 구성 |
|---|---|
| B0 | 임베더 의미 검색만 |
| B1 | B0 + 벡터 검색 + 기호 저장소 |
| B2 | B1 + 명시적 연역 규칙 |
| B3 | B2 + V의 반증/모순 검사 |
| B4 | B3 + 반복 인지 루프 |
| B5 | B4 + 규칙 후보 학습 |
| B6 | B5 + META 구조 변경 |
| B7 | B6 + 학습된 `z_abs` |

누적 정의에는 두 가지 문제가 있다.

1. **귀속 불가.** B3가 B2보다 좋았을 때, 그 이득이 반증 검사 때문인지 B2→B3 사이에서 우연히 바뀐 검색 결과 때문인지 구분되지 않는다. §15.1은 "어느 구성요소가 원인인지 알 수 있게 각 기준선을 유지한다"고 의도했지만, **누적 스택만으로는 귀속이 되지 않는다.**
2. **추가된 구성요소 외의 변화가 섞인다.** 데이터 분할·시드·결정적 정책이 B마다 달라지면, 비교 자체가 무의미해진다. §15.4는 이 4요소를 명시하지만 **B0~B7 전부에서 동일해야 한다고는 쓰지 않았다.**

§12.2는 재귀 비교(A. 메모리 미사용 / B. 단일 검색 / C. 반복 검색)를 설계해 두었지만, 이는 B4 **내부**의 대조이고 **B0~B7 사이의 귀속 문제**는 다루지 않았다.

## 결정

### 1. 고정 조건

**데이터·시드·설정·결정적 정책은 B0~B7 전부에서 동일하게 고정한다**(§15.4). B(k)는 **자기 이전 단계에서 추가된 구성요소 하나만** 켠 상태로 실행한다.

### 2. leave-one-out 대조

각 B(k)에 대해 **추가된 구성요소 하나만 제거한 조건**의 지표를 함께 남긴다.

- B3 → B3-L1: V의 반증/모순 검사만 제거 (B2와 동일 상태)
- B4 → B4-L1: 반복 인지 루프만 제거 (B3과 동일 상태)
- 등

누적 스택과 leave-one-out의 **차이**가 해당 구성요소의 귀속 기여도다.

### 3. 지표별 드롭 지점 표시

성능이 떨어진 경우 **누적 스택에서 어느 B(k)부터 떨어졌는지**를 지표별로 표시한다.

예: 검색 지표는 B4까지 유지되는데 반증 탐지율만 B3에서 하락 → §5.3 진단 순서("입력 추출 오류 → 기억 검색 오류 → 추론 규칙 오류 → …")에 따라 **검색 오류가 아님을 우선 의심**한다.

### 4. B4 내부의 A/B/C 대조 유지

§12.2의 3조건 대조를 B4에서 직접 실행한다. 반복 검색이 정확도를 올리는 대신 비용을 크게 늘리면 **그 결과도 그대로 기록**한다. 반복 검색이 우월하다고 사전 가정하지 않는다.

## 결과

- B(k)와 B(k-1)의 성능 차이가 **한 구성요소에 귀속**된다.
- 성능 저하 시 **원인 구성요소를 지표별로 특정**할 수 있다(Phase 10 통과 기준 "실패 시 원인과 어느 구성요소인지 식별 가능").
- §15.7 "실측하지 않은 수치는 보고하지 않는다"가 B0~B7 비교에도 적용된다.
- §12.2의 재귀 실험 설계가 §15.1의 귀속 요구를 만족한다.

## 잔여 위험

- leave-one-out 대조는 실행 횟수를 늘린다(B0~B4에서 최대 5회 추가). **Phase 10에서 측정 비용을 먼저 산정**하고, 예산을 넘으면 §15.6의 "사전 정의된 허용 범위" 안에서 축소하되 **축소 사실은 기록**한다.
