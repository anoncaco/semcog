# ADR-0005: 저장 구조 트리 교정

- **상태:** 확정 (Accepted)
- **일자:** 2026-10-20
- **관련:** `summary_arch.md` §7.3, §8.10, §15.1.1, §16, §17
- **기반:** 아키텍처 검토 M3

## 배경

§17의 저장 구조 트리와 본문의 요구 사이에 불일치가 3건 있었다. 이는 v1.1에서 `doc/`로 경로를 옮기면서 생긴 것으로 보인다.

| # | 불일치 | 본문 요구 | 트리 상태 |
|---|---|---|---|
| 1 | `configs/goal_rules.yaml` | §7.5, §16 Phase 3이 명시적으로 요구 | **없음** |
| 2 | `data/data_manifest.yaml` | §15.1.1 "버전과 생성 절차를 `data/data_manifest.yaml`에 기록" | **없음** |
| 3 | 파싱 fixture 위치 | §7.3 "`tests/fixtures/parsing/`" | `src/semantic_cognition/parsing/fixtures/` (**충돌**) |

3번은 특히 문제가 된다. **fixture가 두 곳에 있으면 어느 쪽이 정답인지 알 수 없고, 보류 세트가 실수로 개발 세트와 섞일 위험이 생긴다.** §15.1.1의 "분리 규칙"과 §7.3의 "보류 세트는 §15.5 일반화 평가에서만 쓴다"를 기계적으로 검사할 수 없다.

## 검토한 대안

| 대안 | 평가 |
|---|---|
| (a) fixture를 `src/` 하위로 통일 | §7.3이 명시한 경로와 어긋난다. 라이브러리 패키지에 데이터가 들어가는 구조가 된다. **기각** |
| (b) 양쪽 다 유지 | 검사 불가. **기각** |
| **(c) `tests/fixtures/parsing/` 단일화** | **채택** |

## 결정

**§17 트리를 9건 교정한다.**

| # | 교정 | 사유 |
|---|---|---|
| 1 | `configs/goal_rules.yaml` 추가 | §7.5, Phase 3 요구 |
| 2 | `configs/attributes.yaml` 추가 | ADR-0004. §7.3 속성 정규화 규칙의 선언 위치 |
| 3 | `configs/node_types.yaml` 추가 | §8.10 `node_type` 결정 규칙의 선택적 사전 |
| 4 | `data/data_manifest.yaml` 추가 | §15.1.1 요구 |
| 5 | `src/semantic_cognition/parsing/fixtures/` **제거** | ADR-0004. `tests/fixtures/parsing/`이 유일한 위치 |
| 6 | `src/semantic_cognition/parsing/nodes.py` 추가 | §8.10 ConceptNode 생성 코드 위치 명시 |
| 7 | `docs/IMPLEMENTATION_PLAN.md` 추가 | 1차 목표 실행 계획 문서 |
| 8 | `requirements.txt` 추가 | §18.1 의존성 기록 위치 |
| 9 | `docs/ARCHITECTURE.md` 성격 명시 | "파생/갱신본" → 요약 + 링크만. 규범이 아님 |

**추가로, 테스트 파일 위치 규칙을 신설한다.**

§18.2는 `experiments/stageN_*/test_<주제>.py`를 요구하고, §17 트리는 `tests/unit|integration|regression`을 둔다. 둘의 관계가 정의되지 않아 같은 테스트가 두 곳에 복사될 수 있었다.

- `experiments/stageN_*/test_<주제>.py` — 해당 Phase 실험이 **직접 검증하는** 테스트
- `tests/unit/` — 모듈 단위 테스트
- `tests/integration/` — Phase 간 연결 확인
- `tests/regression/` — 기준선 유지 확인. **§7.5.1 개발자 경로 게이트 2(회귀 green)가 실행하는 곳**
- **중복 금지:** 같은 테스트를 두 곳에 복사하지 않는다. 공통 회귀는 `tests/regression/`에 한 번만 둔다.

## 결과

- 문서 본문과 트리가 일치한다.
- fixture 위치가 단일해져, 개발/보류 세트 분리를 자동 검사할 수 있다.
- 테스트 위치 규칙이 명확해져, §7.5.1 게이트 2가 어느 테스트를 돌릴지 특정된다.

## 잔여 위험

- `src/semantic_cognition/parsing/fixtures/` 디렉터리가 이미 생성되어 있으면 **삭제해야 한다.** (Phase 3 착수 전 확인)
